# Dogfood report: 6809 debugger + asm option toggles (2026-07-19)

Companion to `dogfood-report-syscalls-2026-07-19.md` (same session). Closes
most of `VERIFICATION-BACKLOG.md`'s remaining "6809 (secondary priority)"
items that don't need new assembly sources — driven interactively against
`debug /dd/CMDS/linkforktest`, one of that session's syscall regression
binaries, and via `asm ... L S`/`L G` on the existing test sources.

## Debugger — essentially the full command set is now `Live`

`B`/`G`/`M`/`E`/`:` were already `Live` from an earlier session. This pass
added:

| Command | Input | Output | Confirms |
|---|---|---|---|
| Calculator (` 5+3`) | — | `$0008 #00008` | exact documented hex+decimal format |
| `. $100` | set Dot | `0100 FF` | `.`+expr sets and shows |
| *(bare Enter)* | — | `0101 FF` | increments and shows |
| `-` | — | `0100 FF` | decrements and shows |
| `. $200` then `..` | — | `0100 FF` | recalls the *previous* Dot, not current-minus-one |
| `:A` | — | `72` | single-register show |
| `:A $55` then `:A` | set A | `55` | single-register set persists |
| `S $50 $41` (from Dot=`$E8D4`, the module's own entry point) | search | Dot moves to `E8F8`, showing `41` | 2-byte pattern search works from a real code address |
| `$ dir` | shell escape | real `dir` output, returns to `DB:` | shell escape + return |
| `Q` | — | back to `{N1|NN}path:` | quits cleanly |

One real gotcha hit: searching with Dot at `$0` (rather than a real code
address) found nothing — low direct-page memory apparently isn't
meaningful search territory. Always set Dot to something real (a `:`
register dump's `PC` column is a convenient source) before using `S`.

**Only `K` (clear breakpoints) remains untested** in the whole documented
debugger table.

## `asm` option toggles — `L`/`S` confirmed, `G` inconclusive

`asm timeiotest.a L S >lst1.txt` (also run against `childprg.a`) then
`list lst1.txt`:

- **`L`**: produced the full page-headered listing exactly as documented
  (`Microware OS-9 Assembler RS Version 01.00.00 ... Page 001`,
  line-numbered source with object bytes, page breaks at roughly the
  default `D66` depth even with no `D` flag given at all).
- **`S`**: appended a symbol table using exactly the documented
  type-code letters, e.g. `001D E eom      000D L nm       0015 E start`.
- **`G`** (claimed: print every object-code byte a directive generates,
  not just the first): compared `asm timeiotest.a L G >lst2.txt` against
  `asm timeiotest.a L >lst2b.txt` on the same source. The two listings
  were **byte-for-byte identical** for the multi-word `FDB`/multi-byte
  `FCC` directives checked (`dectbl fdb 10000,1000,100,10,1`, a 10-char
  `fcc` string) — both already show every generated byte via continuation
  lines with no flag needed. Either `G`'s real effect is on some other
  category of directive not present in this source, or it's a genuine
  no-op on this build; not resolved either way, reported as inconclusive
  rather than claimed as confirmed or refuted.

`C`/`D<num>`/`E`/`F`/`N`/`W<num>`/`I`/`U` remain individually untested.

## Editor — attempted, inconclusive

`6809/assembly-and-tools.md`'s Editor section (line-and-buffer commands,
`.MAC` macro system) is sourced from the "Assembler/Editor/Debugger
Manual." On this EOU disk:

- `ed` is a **different program entirely** — a mouse/joystick-driven
  full-screen graphics editor (`Ed [filename]`, "80x24 mouse/joystick
  based Text Editor... Runs in a 640x192x2 window"), not line-and-buffer
  at all.
- `edt` launches something identifying itself as "6EDT Version 2.0
  11-30-86" with a plain terminal prompt — a more plausible candidate.
  But a probe in the documented insert syntax (`I 1 hello world`)
  produced an ambiguous, hard-to-parse response (`7 7* 6   6`) that
  didn't clearly confirm or refute the `L n`/`X n`/`I n str` command
  shapes this section documents.

Rather than force a confirmation from an unclear result, this is left
`Manual`. Whoever picks this up next should identify which command (if
any, on this specific community disk) is the vintage Microware line
editor — possibly by checking `6EDT`'s own help/banner more carefully,
or by trying a different disk image that preserves the original tool
under its original name.

## Method note

All of this was driven with `nitros9repl.sh key`/`peek` (raw mode, not
gated `send`) since both `debug` and `edt` have their own sub-prompts —
`send`'s prompt-gate goes silent inside them, the same documented pattern
as BASIC09's `B:`/`E:`. `peek` after every `key` was necessary since
`key`'s own return doesn't wait for or show fresh output.
